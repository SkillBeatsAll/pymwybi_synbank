# Syn Bank — Commercial Intelligence Report

`intelligence-1.0.0` on analytical contract `wallet-1.1.0`. 20 clients x 5 pillars. 100 explanations and 100 banker questions, all generated deterministically — no LLM is called anywhere in this layer, and identical inputs always produce identical words.

This is the **semantic layer**: it turns the wallet model's output into something a Corporate & Investment Banking relationship manager can act on. It adds no data. Every number in every sentence is read from `opportunity_engine.parquet`, and every range from `model_sensitivity.parquet`.

Generated by `analysis/commercial_intelligence_report.py`. Not hand-edited. Companion documents: `MODEL_FINAL_REPORT.md` (the analytical contract), `MODEL_SENSITIVITY.md` (the 36-scenario sweep).

## 1. Terminology rules

The wrong noun is a commercial misstatement, so the vocabulary is enforced in code rather than left to the writer. Every generated string is checked against a list of forbidden phrases by a test that fails the build.

| Pillar | Class | The rand figure is called | Share of wallet? |
|---|---|---|---|
| Transactional / Cash Management | CORE | Addressable Cash Flow | yes |
| FX / Global Markets | CORE | peer-benchmark addressable FX activity | yes |
| Trade Finance | CORE | peer-benchmark addressable trade-finance activity | yes |
| Lending | SUPPORTING | financing opportunity | **never** |
| Investment Banking / Capital Markets | SIGNAL_ONLY | investment-banking opportunity signal | **never** |

**Forbidden anywhere in generated text:** `fee pool`, `fee wallet`, `bank revenue`, `revenue opportunity`, `revenue wallet`, `competitor-held`, `competitor held`, `held by competitors`, `win back`, `win-back`, `lost revenue`, `guaranteed revenue`, `confirmed revenue`, `total opportunity across`, `lending share of wallet`, `investment banking share of wallet`.

> The one that matters most: **Addressable Cash Flow is the client's own operating turnover, not bank income.** R14.31tn of portfolio addressable cash flow is money twenty companies must move through some bank. It is not a fee pool, and no fee figure is estimated on it, because Syn Bank discloses no pricing.

**Lending** is a *financing opportunity* and never receives share-of-wallet language: Syn Bank's data contains no loan book, so there is no observed numerator to divide. **Investment banking** is an *opportunity signal* and never receives a rand figure.

## 2. Recommendation logic

### 2.1 Selecting the primary opportunity

The naive answer is *the biggest rand number*, and it is wrong. The five pillars produce rand on incomparable bases, and their evidence quality differs by a factor of three. So selection multiplies the model's commercial score by what is known about it:

```
selection_score = commercial_opportunity_score
                x role_weight        CORE 1.00 / SUPPORTING 0.85 / SIGNAL_ONLY 0.55
                x confidence_weight  HIGH 1.00 / MEDIUM 0.80 / LOW 0.55
                x (1 - 0.20 if a HIGH-severity diagnostic is open)
                x (1 - 0.10 if the estimate is benchmark-sensitive)
```

Worked through on the brief's own example: a LOW-confidence FX row scoring 0.75 lands at `0.75 x 1.00 x 0.55 = 0.41`. A HIGH-confidence lending row scoring 0.60 lands at `0.60 x 0.85 x 1.00 = 0.51` and wins, whatever the rand amounts are. A test asserts it.

Three slots per client. **Primary** is the highest selection score among pillars that demonstrated headroom. **Secondary** is the next. **Supporting signal** is the highest-scoring remaining pillar that is SUPPORTING or SIGNAL_ONLY class, or is not HIGH confidence — the slot deliberately prefers softer evidence, so the conversation carries the caveated material rather than three confident numbers.

### 2.2 Opportunity status

```
1. rand pillar with headroom below 5% of addressable  -> NO_HEADROOM_DEMONSTRATED
2. SIGNAL_ONLY pillar                                    -> MONITOR (cannot rise higher)
3. HIGH confidence + score >= 0.65 + no HIGH-severity flag  -> PRIORITY
4. score >= 0.45 and not LOW confidence                    -> INVESTIGATE
5. everything else                                       -> MONITOR
```

| Status | Banker action | Client x product rows | Meaning |
|---|---|---|---|
| PRIORITY | Recommend investigation | 14 | High-confidence opportunity with demonstrated headroom and no unresolved model warning. Recommend investigation. |
| INVESTIGATE | Consider investigation | 26 | Credible opportunity carrying either a moderate confidence band or an open model warning. Consider investigation, with the caveat attached. |
| MONITOR | Monitor / validate before pursuing | 56 | Weakly evidenced, benchmark-sensitive, or signal-only. Monitor and validate before pursuing; do not take the rand figure to a client meeting on its own. |
| NO_HEADROOM_DEMONSTRATED | No headroom demonstrated — retention conversation | 4 | The model could not demonstrate headroom: Syn Bank already handles essentially all of the activity the model can size, or the activity could not be sized at all. This is a retention conversation, not a growth one. |

> **A LOW-confidence opportunity can never reach PRIORITY.** No combination of size and score promotes it: `PRIORITY_REQUIRED_BAND = HIGH`. The only route is a named entry in `PRIORITY_OVERRIDES` carrying a written reason — a decision a person makes and signs. The shipped registry is empty (0 entries), and a test asserts both the rule and the emptiness.

The first four are also written as JSON with the same records, NaN rendered as `null`, ready for an API or dashboard to serve directly.

## 11. What this layer does not do

- **No LLM.** Every sentence is a template filled from a published field. The same inputs always produce the same words, and a test asserts it.
- **No new numbers.** The only inputs are `opportunity_engine.parquet`, `client_opportunity_profile.parquet` and `model_sensitivity.parquet`. Nothing is recomputed from the underlying model.
- **No cross-pillar total.** Not in any table, not in any sentence.
- **No ownership claim.** An opportunity is addressable activity not observed in Syn Bank's data — never business a competitor holds, never revenue lost, never revenue confirmed.
- **No dashboard.** That is the next stage, and it should read these tables.
